# SENTINEL — Disaster Response

A disaster intelligence and emergency operations dashboard for coordinating incidents, affected areas, shelters, resources, rescue teams, alerts, and source-attributed decision support.

## Run & Operate

- The managed `artifacts/sentinel: web` workflow starts the Vite app at `/`.
- The managed `artifacts/api-server: API Server` workflow builds and serves Express under `/api`.
- `pnpm install --frozen-lockfile` — restore workspace dependencies.
- `pnpm run typecheck` — typecheck shared libraries and workspace packages.
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas after changing `lib/api-spec/openapi.yaml`.
- `pnpm --filter @workspace/api-server run build` — build the API bundle.
- `PORT=18756 BASE_PATH=/ pnpm --filter @workspace/sentinel run build` — build the web app outside its managed workflow.

### Demo and live configuration

- The app works without external credentials. Choose **Continue in simulated demo** when the sign-in screen is shown; demo edits are in memory and are discarded when the API process restarts.
- Frontend authentication uses `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`.
- The API uses `SUPABASE_URL` and either `SUPABASE_PUBLISHABLE_KEY` or the server-only `SUPABASE_SECRET_KEY`. Requests still carry the user's access token, so Supabase RLS and SENTINEL roles control database access. Never expose the secret key to the browser.
- Apply `artifacts/api-server/supabase/migrations/20261006000100_sentinel_schema.sql` to Supabase before enabling live operations.
- `OPENAI_API_KEY` is optional and server-side only. Without it, Copilot uses deterministic summaries and recommendations from operational records.
- Open-Meteo, flood forecasts, GDACS, USGS, and address search run server-side. Failures retain cached or demo behavior and appear in Data Sources. IMD, NASA FIRMS, and Bhuvan remain disabled until a supported adapter and legitimate access are configured.
- Authenticated clients subscribe to published Supabase operational tables; lists also refresh periodically as a recovery path.

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9, React, and Vite.
- API: Express 5 with esbuild bundling.
- Persistence and authentication: Supabase/PostgreSQL with Row Level Security.
- API contract and validation: OpenAPI, Orval-generated React Query client, and Zod.
- Maps: Leaflet and React Leaflet; address search uses OpenStreetMap Nominatim.
- Deterministic risk and priority rules; optional server-side OpenAI recommendation selection.

## Architecture decisions

- Demo records are simulated and separate from Supabase; demo mutations never write to live records.
- Authenticated PostgREST requests use the user's JWT and RLS; the API checks SENTINEL role before operational writes.
- Risk scores and priorities are deterministic. AI does not generate risk numbers or emergency facts.
- With OpenAI configured, the model selects only from safe recommendations generated by the server; factual responses remain grounded in structured records.
- External feed failures use source-attributed cached or simulated data instead of taking down the dashboard.

## Product

SENTINEL provides overview metrics and map context plus dedicated views for incidents, shelters, resources, rescue operations, alerts, source health, and decision support. Global search and area analysis lead to nearby operational records.

## Gotchas

- Managed artifact workflows provide `PORT` and `BASE_PATH`; direct Vite builds need both values.
- Demo records are volatile and reset on API restart; use Supabase for persistent operational records.
- Apply the Supabase SQL migration before live sign-in can load a SENTINEL role profile.
- Public weather, flood, and geocoding feeds may be delayed, rate-limited, or unavailable. Check source status and classification before operational use.
